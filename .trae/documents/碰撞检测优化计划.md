# ArchiKen 碰撞检测优化计划

> 版本：v1 · 2026-10-17
> 目标：对照 Solibri 碰撞检测能力，补齐「看、管、报」闭环，把碰撞检测从「能算」提升到「好用」。

---

## 一、现状基线

| 层 | 现状 | 位置 |
|---|---|---|
| 内核-硬碰撞 | AABB 宽相位 + 三角形精确求交，返回碰撞点 / 命中三角形对数 | `kernel/app/clash/engine.py` |
| 内核-间隙/净空 | 距离 < 容差（gap_mm / clearance_mm）的邻近扫描 | `kernel/app/clash/classify.py` |
| 内核-冲突矩阵 | 按专业分组、忽略同专业、max_clashes 截断 | `kernel/app/clash/matrix.py` |
| 路由 | `POST /clash/matrix`，mm 换算模型单位 | `kernel/app/routes/clash.py` |
| 前端 | 硬碰撞/间隙/净空开关 + 容差输入、专业矩阵统计、碰撞对列表 | `src/clash/ClashMatrix.tsx` |

**已具备**：硬碰撞 / 间隙 / 净空三类检测、专业矩阵、容差配置。
**缺失**（对照 Solibri）：3D 定位闭环、自定义构件对、结果状态管理、报告输出、重复构件检测。

## 二、优化项与阶段

### Phase 1 — 3D 联动闭环（用户感知最强，先行）
1. 碰撞列表项点击 → 3D 视图定位到碰撞点（复用已有 `contact_point` 字段），绘制碰撞点标记
2. 碰撞对两个构件高亮 + 其余构件半透明（复用视图隔离能力）
3. 列表 ↔ 视图双向选中同步

### Phase 2 — 检测能力补齐
4. 自定义构件对选择集：matrix 接口加 `selection_a` / `selection_b`（ifc_types + 楼层过滤），如「风管 vs 结构梁」；前端加简易配置
5. 重复构件检测（duplicates）：同类型 + bbox 重合度 > 阈值，纯宽相位计算
6. 忽略规则扩展：按类型对忽略、按构件 GUID 白名单（已知可接受碰撞不再报）
7. 碰撞合并分组：同一区域多个碰撞点合并为一个 issue，减少列表噪音

### Phase 3 — 结果管理与报告
8. 碰撞状态：new / 已确认 / 已忽略，L3 持久化，重跑后保留标记
9. 报告导出：接入现有 PDF / XLSX / HTML 报告链，每条碰撞带碰撞点坐标、构件 ID

### Phase 4 — 性能（待真实大模型验证后再做）
10. 宽相位空间哈希/BVH；gap/clearance 包围盒距离近似 + 三角形精算兜底；`.kengeo` 缓存复用

## 三、执行顺序与验证

- 顺序：Phase 1 → Phase 2（4、5 优先）→ Phase 3 → Phase 4
- 每阶段完成后：构造/使用已知碰撞对的测试模型实测，typecheck 通过，debug_log 追加记录，git 提交
- 验证模型：现有 `.data/uploads/` 测试墙 + MEP 样本模型（机电 vs 结构天然有碰撞场景）
