## 一、摘要

现有 V0.1 计划的主线交付物是**单机 Electron 应用**，云端仅以「企业版集群形态」一句话带过（第 2.3 节「双部署形态」），缺少可执行的云端部署路线与阶段归属。

本计划要做的只有一件事：**在不改变「桌面为主」定位的前提下，为总计划补上完整的云端部署章节，并把它落到阶段四/五的工作包、交付物与验收标准里**；同时把散落在选型表、决策记录中的云端相关项对齐。本轮不改动已实现的内核代码。

| 位置 | 现状 | 问题 |

### 2.3 结论

无需推翻现有架构。云端只是**现有 L2/L3 的一种部署形态**，缺的是「可执行的部署路线 + 阶段归属 + 验收口径」。因此本轮是**文档补全**，不是架构重写。

**变更 2｜第 2.2 节选型表新增 6 行（云端相关）**

| 层/模块 | 选定方案 | 决策理由 |
|---|---|---|
| 容器化 | **Docker（多阶段镜像：L2 内核镜像 / L3 业务镜像）** | 云端部署与本地开发同构；内核体积大但可分层缓存 |
| 编排 | **Docker Compose（小规模）→ Kubernetes（企业规模化，非阻塞项）** | 先满足「一键起集群」，k8s 按需演进 |
| 对象存储 | **S3 兼容（企业自建 MinIO / 云厂商 OSS/S3）** | 模型与几何缓存的云端落地；替代本地 FS |
| 鉴权 | **OIDC/OAuth2 + JWT（L3 网关），内核走内部服务令牌** | 云端必须鉴权；内核不直接暴露公网 |
| 任务队列 | **Redis Stream + worker 池（L2 无状态副本）** | 支撑 Autorun 批量与横向扩展 |
| 无头报表 | **Playwright headless Chromium 打包进镜像** | 云端生成 PDF 报告，与桌面共用一套 HTML 排版 |

**变更 3｜第 2.3 节「双部署形态」扩写为独立小节「2.5 云端部署路线」（新增，约 1 屏）**

内容要点（写成可直接照着做的清单）：

1. **部署拓扑**：Ingress/网关 → L3（Koa，2+ 副本，承载鉴权/租户/任务编排/结果分发）→ Redis Stream → L2 worker（FastAPI 内核，N 副本，无状态）→ 对象存储（模型/几何缓存/报告）+ PostgreSQL（项目/规则/结果/权限）。
2. **存储适配层**：在 `kernel/app/config.py` 的 `model_roots()` 与 `geometry_cache_dir()` 之上抽象「存储后端」：`local`（桌面，现状）与 `s3`（云端），由环境变量 `ARCHIKEN_STORAGE=s3|local` 选择；云端模型以对象键定位，几何缓存按「对象键 + ETag」命名落对象存储。
3. **内核运行参数**：`--host` 默认值改为读环境变量 `ARCHIKEN_HOST`（容器内 `0.0.0.0`），端口沿用 `ARCHIKEN_PORT`；内核仅在内网暴露，由 L3 用服务令牌调用。
4. **鉴权与租户**：L3 做 OIDC 登录 → 颁发 JWT；租户维度隔离项目/模型/结果；内核不做用户态判定，只接受 L3 的服务令牌。
5. **任务编排（Autorun / WebChecker）**：L3 投递任务到 Redis Stream → L2 worker 拉取执行（解析→几何→碰撞→规则→报告）→ 结果与产物写回对象存储/PG → 事件回推 L3；任务须**幂等**（同一任务重复执行结果一致）、支持**断点续跑**。
6. **一致性要求（沿用 D5）**：同一份 IFC + 同一套规则，单机模式与云端模式的输出**逐条一致**；云端回归直接复用 `tools/kernel/smoke_test.py` 与语料库。
7. **可观测性与运维**：结构化日志（JSON）、`/health` 保留、指标端点后续按需增加；镜像按内核版本打 tag，建立「内核版本 × 桌面版本」兼容矩阵（沿用 R4）。
8. **资源与成本**：无 GPU 需求；按模型规模给 CPU/内存配额；worker 横向扩展应对批量峰值；缓存命中率是成本关键（几何缓存必须云端共享）。
9. **CI/CD**：镜像构建 + 单机集群一致性回归纳入流水线（当前仓库已有 CI 规划）。

**变更 4｜第 2.4 节难点 6 增补云端相关一句**
