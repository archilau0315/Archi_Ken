## 一、规则结构（DSL v1）

最小规则：

```json
{
  "id": "door-min-width",
  "name": "门最小宽度",
  "category": "通用规则",
  "severity": "error",
  "target": { "ifc_type": ["IfcDoor"], "where": [] },
  "check": { "type": "property", "pset": "Pset_DoorCommon", "prop": "ClearWidth", "op": ">=", "value": 800, "unit": "mm" },
  "message": "门宽 {actual} 小于最小要求 {expected}",
  "reference": "GB 55019-2021 第 2.1.3 条",
  "reference_en": "GB 55019-2021 §2.1.3"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| id | ✅ | 全库唯一，小写连字符（域-构件-检查项，如 `fire-wall-rating`） |
| name / name_en | 建议 | 显示名；内置模板需双语 |
| category / category_en | 建议 | 分类（无障碍/消防/净高…），缺省「通用规则」 |
| severity | 建议 | error / warning / info，缺省 error（**定级见第四节**） |
| target | ✅ | 目标选择器（见第二节） |
| check | ✅ | 检查定义（见第三节） |
| message / message_en | 可选 | 结果说明模板，占位符：`{name}` `{actual}` `{expected}` `{related_name}` |
| reference / reference_en | 建议 | 规范出处，写入报告；双引格式见第五节 |

## 二、target 选择器

```json
{ "ifc_type": ["IfcDoor"], "where": [条件...] }
```

- `ifc_type`：数组或 `"*"`（全部 IfcProduct）。**IFC 版本不存在的类型自动跳过**（如 IFC2x3 无 IfcDuctSegment），不会报错。
- `where`：条件列表，**条件之间为 AND**。
- 条件两种取值来源：
  - 实体属性：`{"attr": "Name", "op": "contains", "value": "门"}`
  - 属性集：`{"pset": "Pset_DoorCommon", "prop": "FireRating", "op": "==", "value": "甲级"}`
- OR 条件组 `any_of`（组内任一满足即该条件成立）：

```json
{ "any_of": [
    { "attr": "Name", "op": "contains", "value": "卫生间" },
    { "attr": "Name", "op": "contains", "value": "浴室" }
] }
```

算子：`==` `!=` `>` `>=` `<` `<=` `in` `contains` `startswith` `endswith` `matches`（正则）`exists` `not_exists`。

## 三、check 检查类型（8 种）

| type | 用途 | 关键字段 |
|---|---|---|
| property | 属性比较 | pset+prop+op+value+unit+missing（violation/pass/skip） |
| intersection | 几何相交（碰撞） | other（选择器） |
| clearance | 最小净距 | other、axis（x/y/z/all）、value、unit |
| headroom | 顶部净高 | other（遮挡构件）、value、unit |
| dimension | 构件净尺寸 | axis（x/y/z/min）、value、unit |
| duplicate | 重复构件 | size_tolerance、center_tolerance（比例） |
| count | 构件计数 | op、value、group_by（可选 `"storey"` 按楼层分组） |
| containment | 空间包含 | other（目标空间选择器）；目标包围盒中心须落在空间包围盒内 |

示例——每层安全出口 ≥2：

```json
"check": { "type": "count", "op": ">=", "value": 2, "group_by": "storey" }
```

示例——消火栓须位于走道：

```json
"check": { "type": "containment", "other": { "ifc_type": ["IfcSpace"], "where": [
  { "any_of": [{ "attr": "Name", "op": "contains", "value": "走道" },
               { "attr": "Name", "op": "contains", "value": "前室" }] }
] } }
```

## 四、severity 定级约定

| 级别 | 适用 |
|---|---|
| error | 违反现行 GB 强制性条文，且阈值已按规范原文核对、并经模型验证 |
| warning | 违反规范但阈值存疑待复核；或建模质量风险较高 |
| info | 数据完整性提示、建议项 |

**铁律：error 级阈值必须核对现行规范原文后定死；拿不准的一律 warning/info，并在 reference 末尾标注「阈值待按现行规范原文复核」。**

## 五、reference 规范出处写法

- 权威出处用**现行有效规范**（GB 55xxx 通用规范），写到条/款级：`GB 55037-2022 第 6.4.2 条`
- 旧规范条文以双引格式保留备查：`GB 55037-2022 第 6.4.2 条（原 GB 50016-2014 第 6.4.11 条）`
- 禁止引用已废止规范作为权威出处。

## 六、单位约定（重要）

- **几何类检查**（clearance/headroom/dimension/containment）：ifcopenshell 几何输出**恒为米**，与文件声明单位无关；规则阈值照常写 unit（mm/cm/m），引擎按固定因子换算，无需关心文件单位。
- **属性检查**（property）：读 Pset/Qto 原始值，按**文件声明单位**换算；unit 缺省 `model` 表示不换算。
- count/duplicate/intersection 与单位无关。

## 七、已知适用限制（写规则前先读）

1. **dimension 不适用斜板/坡屋面**：包围盒 Z 向含坡度投影，厚度判定失真；只用于墙、梁、平板等规则构件。
2. **IFC2x3 机电构件**：走 `IfcFlowSegment`（无 IfcDuctSegment/IfcPipeSegment）；跨版本规则 ifc_type 应并列 `"IfcFlowSegment"`。
3. **命名关键词匹配（attr Name contains/matches）误报风险高**：依赖建模命名习惯，只适合做 warning/info 级规则；楼层命名正则需兼容 `B1/1F/F1/Level/ground`。
4. **containment 是包围盒级判定**：空间形状不规则（L 形走道）时边界构件可能误判，优先 info/warning 级。
5. **count group_by=storey** 依赖构件正确分配楼层；未分配楼层的构件归入「(未分配楼层)」组。
